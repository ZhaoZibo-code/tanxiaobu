01 / Why

The Gap

低碳生活，
常常停在「想一想」。

行动发生在细节里：少开一盏灯、少剩半份饭、把旧手机交出去。但这些事很少被留下来，也很难被解释清楚。

01 — 做了，没留下

做过的事，散落在日常里

回看时只记得「好像做过」，说不清做过多少、什么时候做的。

02 — 有数字，没依据

有数字，却说不清怎么算

数字一旦脱离来源和适用条件，就很难被信任，也无法复核。

03 — 有热情，难坚持

缺少积累，也很难走远

没有反馈的坚持，往往在第三周就悄悄停止了。

我们的落点：把「记录 → 解释 → 反馈」做成一条闭环 02

02 / Solution

One Journal, Three Moves

一本账本，
三个动作。

01Record

记录一次真实行动

选场景、填有依据的数量、看清核算依据，再保存成一条可查询的本地记录。

02See

看见变化，也看见理由

按时间与类别查看趋势，点开任意一条都能回到它的因子、假设与来源。

03Keep

让坚持有一点仪式感

正减排行动点亮七日火花，每日任务与虚拟奖励把「再做一次」变得具体。

04 / Transparency

Traceable Estimate

数字有依据，
历史可追溯。

示例 · 已确认节约外购电量
1 kWh × 0.5306 = 0.531kg CO₂e
来源 2023 全国平均电力因子 单条末尾按克舍入

只输入有依据确认的节电差值，不是总用电量；结果是给定条件下的参考估算，不是实时边际排放，也不是核证减排量。

历史快照 catalog v1.0 → catalog v1.1 → 旧记录仍按当时因子呈现
规则版本升级不会静默改写历史记录 05

06 / Engineering

Built To Be Trusted

离线优先，
边界清晰。

ArkUI 页面只调用公共业务接口
→
业务服务核算 / 任务 / 统计 / 备份
→
RDB 本机库记录 · 积分流水 · 奖励
跨记录 · 任务 · 积分的写入走同一事务，提交成功后只通知一次

不需要账号，也能用完整流程

记录、统计、任务、科普、备份全部在本机完成；没有网络时，核心流程照常运行。

可更正，也可对账

更正或撤销后，关联积分同步回退；备份带版本与校验，CSV 报表可直接核对。

核算不写库 · 仓储不定义积分 · UI 不拼 SQL 07
