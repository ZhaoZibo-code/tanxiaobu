# UI 情报：离线个人碳足迹应用

日期：2026-10-28。用途：为中文普通用户的 OpenHarmony ArkUI 应用提供信息架构、交互与视觉参考；这是桌面研究，不是产品实现、授权审查或 API12 实测。

## 当前产品基线

项目是离线个人行为记录与反馈工具：出行、节水节电、旧物回收、光盘行动；用户录入行为并查看所存减排结果、历史、统计、任务/奖励、科普和本地数据管理。统计应如实呈现已存数据，不能用虚构累计数填空。现有应用代码只有基础壳：五栏导航（概览、记录、统计、任务、我的）、日期标题、加载/空/错误/未就绪状态；主题变量为浅灰绿背景、深绿文字与主色、白卡片、16px正文、圆角卡片。生产 feature 页面尚未出现。来源：[Index.ets](../../../app/entry/src/main/ets/pages/Index.ets)、[Theme.ets](../../../app/entry/src/main/ets/common/design/Theme.ets)、[ARCHITECTURE.md](../../ai-dev/ARCHITECTURE.md)、[CONTRACTS.md](../../ai-dev/CONTRACTS.md)。

## 信息架构建议

1. **概览**：显著显示所选周期的“已记录减排”与记录数；当前无数据时明确空状态，并给出“记录一次行动”主入口，不展示虚构树木、汽车里程或累计数。次级入口放趋势、分类分布、今日任务与最近记录。
2. **记录**：以四类入口开始，选择具体有定义的行为后再录数量/单位/日期；基准差额规则先用普通中文说明参照情景并要求确认。确认前展示计算步骤、估算条件、来源/适用范围；保存后给出明细和可更正入口。
3. **统计**：日/周/月/年切换与分类筛选；总净值和正向减排分开。趋势图同一量纲、零基线清楚，负值向下或单独标记；图例、文字数值与颜色并用。导出使用同一快照口径。
4. **任务**：把任务资格、进度、领取状态和积分分开展示；仅有效记录驱动进度。奖励明确标注“应用内虚拟”，不暗示真实植树、捐赠或权益。
5. **我的**：本地数据管理、备份/恢复/CSV、偏好设置、低碳知识与建议。将导出与恢复作为清晰可发现的二级入口，恢复前呈现文件摘要和不可逆影响确认。
6. **全局状态**：统一加载、空、未就绪、失败/可重试状态；错误文案说清可做的下一步。离线默认应是常态，不要用断网警告制造焦虑。

## 视觉方向（供 UI 设计工程师选择）

### A. 温润自然账本（推荐）

沿用现有浅灰绿底、深墨绿文字与低饱和主绿；白色数据卡片配细分隔线，辅以少量暖沙色承载行动分类，数字采用清晰等宽或 tabular 样式。图表克制、网格轻、标签直接；插画只用于空状态且用原创抽象叶片/循环符号。推荐理由：延续现有 Theme，可信、安静、中文可读，适合长期记录；不用外部图片/字体/依赖，且最容易在 ArkUI/API12 原生实现。

### B. 清晰数据仪表

中性浅底、高对比墨色，以青绿作为唯一主数据色，橙/红只表示警示或负向，不用渐变制造“减排很大”的错觉。首页突出周期数值与趋势，记录表格/筛选强调效率。适合希望统计是核心的用户；需避免过度企业化或把个人行为变成 KPI。

### C. 轻量行动卡片

更明亮的暖白底与柔和绿色，四类行动以不同图标和短句卡片呈现，任务与科普融入渐进式提示；用小而明确的反馈强化“记录—理解—继续行动”。适合新手引导，但需控制装饰和游戏化，不能让徽章/连续打卡压过真实数据与证据说明。

**建议首选 A**，以 B 的图表可读性和 C 的新手入口作局部补充；不推荐整套复制任何案例站或设计系统。实施时由 UI 设计工程师以现有 Theme 作为起点，先做概览/记录/统计三屏信息层级稿，再按本机 API12 原生能力验证组件与图表，不添加未审批依赖。
